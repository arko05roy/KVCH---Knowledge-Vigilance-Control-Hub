# 004 — AI Architecture

## Purpose

Define KVCH's AI boundaries for role-specific reporting. AI never authorizes access, grants a capability, approves an artifact, performs an escalation, changes case state, or makes an enforcement decision.

## Provider

KVCH uses a user-supplied Groq API key for v1 AI role-report inference. The API key remains server-only. Exact model selection is deferred; KVCH records the model identifier actually used, alongside the prompt version, source projection hash, generation timestamp, status, and output reference in the Company audit stream.

## Role-report boundary

KVCH first constructs and authorizes a Role Projection. Redaction and access-control checks happen before an AI request. The report service receives only that projection and returns a structured report appropriate to its recipient. The resulting report is stored as a generated artifact attached to the case; it never becomes an authorization source.

When a case is first routed or manually sent upstream, KVCH creates the newly authorized Role Projection before requesting its AI Role Report. AI does not choose whether a route advances.

## Safety requirements

- Prompts and structured output schemas are versioned.
- Model output is schema-validated before it can be displayed.
- Raw secret values and evidence excluded from a Role Projection never enter the model request.
- The service enforces Company-scoped access, rate limits, cost limits, retries with backoff, and failure recording.
- A failed generation never blocks case creation, notification, acknowledgement, remediation, closure, or manual escalation; the dashboard shows its generation state and supports a retry by an authorized user.
